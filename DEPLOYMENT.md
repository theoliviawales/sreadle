# Sreadle Deployment Plan

How to take Sreadle (Sight Readle), a daily rhythm sight-reading game, from a
working prototype to a public website anyone can play every day.

## What we are deploying

Sreadle is a fully static, client-side web game:

- One self-contained `index.html` (inline CSS and JavaScript, no build step,
  no framework, no backend, no accounts, no database).
- The daily rhythm is computed in the browser from the date. Days 1 to 10 are
  hand-written rhythms stored in the page; Day 11 onward is generated by a
  seeded pseudo-random generator keyed to the puzzle number, so every player
  gets the same rhythm on the same day with no server involved.
- Player stats (streak, best scores) live in the player's own browser
  localStorage. Nothing is uploaded anywhere.

Because there is no server logic, deployment is just "put one HTML file on a
static host." Everything below follows from that.

## Recommended path: GitHub Pages

1. **Repository** (done): `github.com/theoliviawales/sreadle`, public, `main`
   branch. The game ships as `index.html` at the repository root.
2. **Turn on Pages**: in the repository, Settings, then Pages, then set
   "Build and deployment" to deploy from branch `main`, folder `/ (root)`.
   The site appears at `https://theoliviawales.github.io/sreadle/` within a
   few minutes.
3. **Verify**: open the URL on a phone and a desktop browser, play a full
   round, confirm audio starts after the first tap (mobile browsers require a
   user gesture for WebAudio), and confirm the displayed puzzle number matches
   the current date in America/Los_Angeles.
4. **Updates**: any push to `main` redeploys automatically. There is no build
   to break; test locally by opening `index.html` in a browser before pushing.

Cost: $0. HTTPS is automatic. Uptime and bandwidth are more than sufficient
for a daily-game audience.

## Custom domain (optional, recommended once it has players)

1. Buy a domain, for example `sreadle.com` or `playsreadle.com`, from a
   registrar with free WHOIS privacy (Cloudflare Registrar or Porkbun are
   good defaults). Expect roughly $10 to $15 per year.
2. Point it at GitHub Pages: add the domain under Settings, then Pages, then
   Custom domain, and create the DNS records GitHub shows (four A records to
   GitHub Pages IPs for an apex domain, or one CNAME for `www`).
3. Enable "Enforce HTTPS" once the certificate provisions (usually under an
   hour).
4. Alternative: host on Cloudflare Pages instead and attach the domain there;
   Cloudflare gives faster global caching and privacy-friendly analytics in
   one dashboard. The same single file works unchanged.

## Make it feel like a real daily game

- **Midnight rollover**: the puzzle number is derived from the date in
  America/Los_Angeles, so a new Sreadle appears at midnight Pacific for
  everyone. This is a deliberate choice (it is the home timezone); document it
  on the page so players are not surprised.
- **Share results**: the in-game "Copy results" button produces Wordle-style
  text (puzzle number, accuracy, score, per-measure squares). Add Open Graph
  meta tags and a 1200x630 share image so links pasted into chats and social
  apps unfurl with a title and picture.
- **Add to home screen**: add a web app manifest and an icon so the site
  installs like an app on phones. No app store, no review process.
- **Analytics (privacy-friendly)**: Cloudflare Web Analytics or Plausible, a
  single script tag, no cookies, just daily player counts and referrers.
  GitHub Pages itself provides no visitor stats.

## Quality checklist before announcing it

- Play Days 1 to 10 and a few generated days (11+) on a real phone; confirm
  every measure sums to exactly 4 beats and generated days are identical
  across two different browsers (determinism check).
- Test in Safari iOS and Chrome Android: audio unlock, tap latency, layout in
  portrait, no double-tap zoom during play.
- Check the results/share text on a phone and paste it into a message to
  confirm formatting survives.
- Confirm the page works fully offline after first load is NOT required, but
  nothing on the page should depend on external fonts or CDNs being up.

## If it outgrows static hosting (future options, not needed now)

- **Accounts and cross-device streaks**: add a small backend (Supabase or
  Firebase) for sign-in and synced stats. This is the only feature that truly
  needs a server.
- **Leaderboards**: same backend, one table of daily scores; add anti-cheat
  sanity checks (max plausible score per puzzle) before trusting submissions.
- **Hand-authored seasons**: if generated rhythms ever feel stale, ship a
  JSON file of new hand-written days and have the page prefer authored days
  over generated ones. Still static, still free.
- **Native apps**: wrap the same page with Capacitor for the iOS/Android
  stores. Only worth it for push notifications ("today's Sreadle is ready"),
  which a website cannot send reliably on iOS.
